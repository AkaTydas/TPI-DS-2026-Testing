Paso 2: Actualización de Contrato OpenAPI 3.1.0 (RNF-03)

En C:\Users\mateo\OneDrive\Desktop\2026-TPI-main\contratos\m9_reservas\openapi.yml el archivo de la cátedra está vacío (6 líneas). Tienen que llevar el contrato de su grupo ahí. Pero antes hay que actualizarlo de OpenAPI 3.0.3 a OpenAPI 3.1.0 (que es la versión del repositorio central).

Diferencia 1: Cabecera y Sintaxis Nullable

En OpenAPI 3.0 se usaba nullable: true. En OpenAPI 3.1.0 se usa sintaxis JSON Schema pura:

❌ OpenAPI 3.0.3 (Como está hoy): 
openapi: 3.0.3
...
alias:
  type: string
  nullable: true
✅ OpenAPI 3.1.0 (Como debe quedar): 
openapi: 3.1.0
...
alias:
  type: [string, "null"]
Diferencia 2: Catálogo de Eventos Asíncronos

El RNF-03 exige: "Eventos documentados en un catálogo común". M6 (Grupo 12) ya agregó sus esquemas de eventos al final del contrato. M9 debe hacer lo mismo en `components/schemas`:

# Esquema de evento para M8
ReservaEventoEnvelope:
  type: object
  required: [eventoId, tipoEvento, ocurridoEn, reservaId]
  properties:
    eventoId: { type: string, format: uuid }
    tipoEvento:
      type: string
      enum: [RESERVA_CREADA, RESERVA_CONFIRMADA, RESERVA_MODIFICADA, RESERVA_RECORDATORIO, RESERVA_ACTIVADA, RESERVA_CANCELADA, RESERVA_VENCIDA]
    ocurridoEn: { type: string, format: date-time }
    reservaId: { type: string, format: uuid }
    datos: { type: object }

Paso 3: Corrección de los 3 Bugs Críticos

Estos son los 3 puntos donde el código actual de tu grupo falla ante situaciones reales de producción o permisos:

Bug 1 Clientes HTTP haciendo fallback a mocks cuando `USE_EXTERNAL_MOCKS=false`

Archivos: src/clients/m2Client.ts, m4Client.ts, m5Client.ts y m7Client.ts.
Solución: En el bloque `catch`, verificar si `config.services.useExternalMocks` está activo. Si está en `false`, lanzar un `AppError(503)` con formato RFC 7807.

❌ Código Actual (`m4Client.ts` línea 250): 
catch (err: unknown) {
  console.warn(`[M4Client] Error llamando a M4... Usando fallback mock.`);
  return this.mockValidarYEstimar(data);
}
✅ Código Corregido: 
catch (err: unknown) {
  if (config.services.useExternalMocks) {
    return this.mockValidarYEstimar(data);
  }
  throw new AppError({
    status: 503,
    title: 'Dependencia no disponible',
    detail: `El Módulo de Ubicación (M4) no respondió: ${(err as Error).message}`
  });
}
Bug 2 Rol `CONDUCTOR` recibiendo 403 Forbidden en `GET /reservas/:id`

Archivo: src/services/reservationService.ts (método `obtenerPorId`, línea 184).
Solución: Sumar a `CONDUCTOR` dentro de los roles autorizados a consultar la reserva.

❌ Código Actual: 
const esAdmin = user.roles.includes('OPERADOR') || user.roles.includes('SERVICIO');
if (!esAdmin && user.sub !== reserva.clienteId) {
  throw new AppError({ status: 403, title: 'Acceso no autorizado' });
}
✅ Código Corregido: 
const autorizado =
  user.roles.includes('OPERADOR') ||
  user.roles.includes('SERVICIO') ||
  user.roles.includes('CONDUCTOR') ||
  user.sub === reserva.clienteId;

if (!autorizado) {
  throw new AppError({ status: 403, title: 'Acceso no autorizado' });
}
Bug 3 Reuso de `claveIdempotencia` con cuerpo distinto debe responder 422

Archivo: src/services/reservationService.ts (método `crearReserva`).
Solución: Si la clave de idempotencia ya existe en la base, verificar que el `clienteId`, `origen`, `destino`, `tipoVehiculo` y `fechaHora` sean idénticos. Si cambiaron datos, responder `422 Unprocessable Content`.

RF-9.9 Scheduler de Activación Automática al Llegar la Hora

Qué agregar: Crear `src/services/schedulerService.ts` que se inicialice en `src/index.ts` (solo si no es entorno de testing) para revisar periódicamente las reservas listas para despacho: 

// En src/services/schedulerService.ts:
import { db } from '../config/database';
import { ActivationService } from './activationService';

export class ReservationScheduler {
  private static timer: NodeJS.Timeout | null = null;

  public static start(intervalMs: number = 30000) {
    if (process.env.NODE_ENV === 'test') return;

    this.timer = setInterval(async () => {
      try {
        // Busca reservas CONFIRMADAS que arranquen en los próximos 20 minutos y no tengan solicitud M5
        const query = `
          SELECT id FROM reservas 
          WHERE estado = 'CONFIRMADA' 
            AND solicitud_despacho_id IS NULL
            AND fecha_hora <= NOW() + INTERVAL '20 minutes'
            AND fecha_hora >= NOW() - INTERVAL '5 minutes'
        `;
        const res = await db.query(query);
        for (const row of res.rows) {
          await ActivationService.activarReserva(row.id, { sub: 'scheduler-m9', roles: ['SERVICIO'] });
          console.log(`[Scheduler] Reserva ${row.id} activada automáticamente hacia M5.`);
        }
      } catch (err) {
        console.error('[Scheduler Error]', err);
      }
    }, intervalMs);
  }

  public static stop() {
    if (this.timer) clearInterval(this.timer);
  }
}
